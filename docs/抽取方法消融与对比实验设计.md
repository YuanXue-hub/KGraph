# 抽取方法消融与对比实验设计：KGraph vs Semantica

> 目的：验证本项目 LLM 抽取流水线（两阶段 + 谓词锚点词表 + 时间标定 + 证据回溯 + W 校验墙）相对基线与 Semantica 式设计的效果，并定位各组件贡献。与《评估方法消融与对比实验设计.md》配套：本文管"抽得准不准"，彼文管"评得稳不稳"。
>
> 约束：不写实验脚本，全部通过前端抽取 + 评估界面完成，数据以任务/评估记录 id 登记。

## 二、实验设计

### E1 版本演进对比（主实验，半数数据已有）

**问题**：V0→V1→V2→V3 的每次改动带来了什么？

**设计**：三份语料 × 四个版本。已有数据先行登记，缺口补跑：

| 语料 | V0 旧版 | V1 词表版 | V2 精简版 | V3 当前版 |
|---|---|---|---|---|
| C1 诉讼 | ✅ 任务 2094406639339233282（45 关系，泛化谓词 14+） | ✅ 09-02 验证跑（41 关系，泛化谓词 0） | ❌ 补跑 | ❌ 补跑 |
| C2 三国 | ❌ 补跑 | —（跳过，用 V3 数据即可） | ❌ 补跑 | ✅ 任务 2095509498512379905（66 关系） |
| C3 对照 | ❌ 补跑 | — | — | ❌ 补跑 |

**观测指标**（每格登记）：

1. 关系数 / 实体数（召回规模）
2. 泛化谓词条数（实施/涉及/涉及对象/涉原告/涉被告/相关——V0 的病灶）
3. 事件论元边占比（事件实体的 执行者/作用对象/参与方 边 ÷ 事件实体数，V3 的设计目标）
4. 孤立实体率（内在指标直接给出）
5. 评估 five 指标分 + overall（裁判统一 deepseek-chat 新版）

**预期结论形态**：一张"版本 × 语料 × 指标"矩阵，展示：
- V0→V1：泛化谓词 14+ → 0，谓词合理性大幅提升（评估已证 0.425→0.78+）
- V1→V2：召回崩塌（45→14）——证明"Semantica 极简不能直接照抄，它有多方法 fallback 兜底，我们纯 LLM 必须带召回指令"
- V2→V3：召回恢复（14→66）且泛化谓词保持 0

### E2 金标探针准确率（准确性）

**问题**：抽出来的东西对不对（不只是多不多）？

**设计**：C2 三国语料埋点已人工核对（写语料时同步记录金标清单），抽取后逐条比对：

| 探针类型 | 数量 | 金标示例 | 判定标准 |
|---|---|---|---|
| 否定关系 | 3 | 周瑜-并无冲突->诸葛亮（原文"与诸葛亮并无直接冲突"） | 抽出且谓词为否定表述 = 命中 |
| EXPIRED 型 vt_to | ≥2 | 刘备受任县尉后弃官；刘表 208 年病逝 | vt_to 有值且指向正确 = 命中 |
| 完整时间链 | ≥3 | 184 起义 / 196 迎献帝 / 208 赤壁 | vt_from 精度正确 = 命中 |
| 事件实体命名 | 5 | "刘备三顾茅庐拜访诸葛亮"（完整动宾短语） | 抽出且形态规范 = 命中 |
| 指代消解 | ≥3 | "其次子"→刘琮；"其"→曹操处死董承语境 | 指代词不建实体、归并到本体 = 命中 |
| 因果链 | ≥2 | 黄巾之乱→朝廷威信崩塌→州牧拥兵 | 抽出因果谓词边 = 命中 |

**产出**：每版本探针命中率 = 命中数/金标总数（分类型给出）。这是唯一需要人工参与的实验（每版本约 20 分钟核对）。

### E3 谓词词表消融（组件贡献）

**问题**：谓词质量提升来自词表，还是来自别的？

**设计**：C1 诉讼语料（泛化谓词高发区）上跑三配置：

| 配置 | 谓词指令 | 预期 |
|---|---|---|
| A | 无词表无禁令（V0 形态） | 泛化谓词 10+ |
| B | 仅禁令（禁止实施/涉及类，不给词表） | 泛化谓词归零但谓词多样性下降，可能出现生造词 |
| C | 词表 + 禁令（V1/V3 形态） | 泛化谓词归零且谓词规范聚集 |

**观测**：泛化谓词数、谓词种类数（去重）、生造谓词数（词表外自造，如"文本共现关联"）、谓词合理性评估分。

> B 配置通过临时编辑 prompt_builder 中谓词小节实现，跑后 git checkout 还原。

### E4 时间标注消融（组件贡献）

**问题**：时间标定表 + few-shot 带来了什么？

**设计**：C2 三国语料（时间信号最密）跑两配置：

| 配置 | 时间指令 | 预期 |
|---|---|---|
| A | 仅一句"提取时间信息"（V0 形态） | 时间漏标多、置信度无区分度 |
| B | 标定表 + 5 few-shot（当前形态） | 双时态指标 1.0（已三次实测） |

**观测**：vt 非空关系占比、双时态评估分、confidence 分布（B 预期分层：1.0/0.9/0.85/0.75 各档都有样本）。

### E5 对比实验：KGraph V3 vs Semantica S1（跨方法）

**问题**：两套设计在同一语料、同一模型、同一评估裁判下的直接差异？

**设计**：C1 + C2 两份语料，S1 配置 = 将 prompt_builder 的词表/规则段替换为 Semantica 原版 prompt 中译（related_to/part_of/located_in/created_by/uses/depends_on/interacts_with + 时间标定表），管道其余不变（证据回溯、W 校验墙照走）。

**观测**：

1. 五指标 + overall（同一裁判下直接可比）
2. 结构指标：泛化谓词率（Semantica 的 related_to 按我们的标准算弱谓词）、事件论元缺失率（其无事件建模）
3. 探针命中率（E2 金标复用——Semantica 无否定关系/双时态建模，预期否定探针 0 命中）

**预期结论形态**：

| 维度 | KGraph V3 | Semantica S1 | 说明 |
|---|---|---|---|
| 谓词规范性 | 高 | 低（related_to 泛化） | 我们赢 |
| 时间标注 | 双时态+标定 | 仅 valid_from/until | 我们赢 |
| 否定关系 | 否定谓词捕获 | 不支持（抽成普通关系） | 我们赢 |
| 召回规模 | 看实测 | 看实测 | Semantica 词表英文通用域，中文语料可能漏抽 |

> 注意公平性：S1 是"prompt 层对比"而非"系统层对比"——Semantica 完整系统的分块/去重/多方法 fallback 我们未复刻（那是 P2 切分实验的事）。结论表述必须限定为"提示词设计层面"。

### E6 模型敏感性（稳健性）

**问题**：V3 抽取方法对不同能力的抽取模型是否稳健？

**设计**：C2 语料 × {deepseek-chat, v4-flash}（v4-pro 可选）。已有数据：v4-flash 在 V3 下曾产出 26 关系且「涉及」滥用 14 次（09-02 实测），deepseek-chat 41 关系谓词全规范。

**观测**：关系数、泛化谓词数、探针命中率、评估分——量化"prompt 设计对弱模型的约束力边界"。

**预期结论**：词表+指令对强模型有效（chat 谓词全规范），对弱模型部分失效（flash 滥用兜底谓词）→ 支撑"抽取模型分级推荐"的产品决策（flash 标注"速度优先"或禁用）。

## 四、判读标准

| 实验 | "方法有效/更优"的量化标准 |
|---|---|
| E1 | V3 相对 V0：泛化谓词 ≥90% 消除 且 关系数不下降超 20%（召回换质量可接受边界） |
| E2 | V3 探针总命中率 ≥80%，其中否定关系探针 ≥2/3 |
| E3 | 配置 C 相对 A：泛化谓词归零；配置 C 相对 B：谓词种类数更多且无生造词 |
| E4 | 配置 B 的 vt 非空占比与双时态评估分均显著高于 A |
| E5 | V3 在五指标 overall 上 ≥ S1，且否定/时间探针 V3>S1（结构性优势项全胜） |
| E6 | chat 与 flash 的差距量化后给出模型分级建议 |

**整体结论模板**：
- 版本演进：V0→V3 泛化谓词 ___→___，overall ___→___，召回 ___→___
- 组件贡献：词表贡献___，时间标定贡献___，召回指令贡献___（V2→V3 关系数 ___→___）
- 对比 Semantica：overall ___ vs ___；结构性优势项（否定/双时态/事件论元）___
- 模型敏感性：chat/flash 探针命中 ___ vs ___，推荐策略___

## 五、有效性威胁与控制

| 威胁 | 控制 |
|---|---|
| Semantica prompt 中译后失真（原版英文） | 保留原版谓词英文词表（LLM 中文语料下可理解），仅指令框架中译；diff 存档 |
| S1 未带 Semantica 的分块/fallback，对比不公平 | 结论限定"提示词设计层面"；系统层对比留给语料分块实验 |
| 单次抽取无重复（抽取本身也有 LLM 方差） | 每配置关键格子（E1 的 V3 列、E5 双方）补跑 1 次看一致性；抽取方差≪评估方差（后者已压到 0.002） |
| Neo4j 临时写入污染 | 独立 modelId + 实验后删除；result JSON 本身已含全部数据，图谱写入可跳过 |
| 探针人工核对主观性 | 金标清单在抽取前写定（语料设计时同步埋点），核对只比对存在性不重判质量 |
| C2 语料由 AI 生成可能存在模型熟悉偏差 | 三个裁判模型与语料生成模型不同源；C1/C3 为真实/传统语料作对照 |

## 六、执行顺序建议

1. **E1 补跑**（C1×V2/V3、C2×V0/V2、C3×V0/V3，共 6 次抽取+评估）：当前代码零改动
2. **E2**：对上述所有抽取结果做探针核对（每版本 20 分钟人工）
3. **E5**：临时替换 S1 prompt，C1/C2 各跑 1 次，还原代码
4. **E3/E4**：临时改谓词/时间小节各跑 1-2 次，还原
5. **E6**：C2×v4-flash 重跑 1 次（V3 prompt 下）
6. 汇总登记表 → 填结论模板 → 回填附录

预计总投入：约 15 次抽取调用 + 15 次评估调用（deepseek-chat，单次成本很低）+ 约 2 小时人工核对。

## 附录 A：两套方法设计差异备忘（对比依据）

| 维度 | KGraph V3 | Semantica |
|---|---|---|
| 谓词治理 | 中文 5 类锚点词表（含因果类、事件论元角色类）+ 泛化谓词禁令 | 英文 7 词锚点（related_to 等）+ 允许变体 |
| 时间建模 | vt_from/vt_to + 否定谓词（原 status 三态已简化） | valid_from/valid_until（扩展功能，默认关） |
| 否定关系 | 否定谓词直接表达（并无冲突/并未担任） | 不支持 |
| 事件实体 | 一等公民：完整动宾短语命名 + 论元角色谓词 | EVENT 仅 7 类实体之一，无规范 |
| 证据回溯 | evidenceText 强制 + find() 逐字校验，无证据丢弃 | 无证据字段 |
| 指代消解 | 阶段1 内联 coreferenceChains | 独立可选组件，默认不跑 |
| Prompt 风格 | Semantica 式轻结构 + 穷尽提取召回指令 | 极简 3-4 条指令（召回靠多方法 fallback） |
| 召回兜底 | 纯 LLM 单调用，指令承载召回 | pattern/regex/rules/LLM 四级 fallback |
