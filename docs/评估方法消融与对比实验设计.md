# 评估方法消融与对比实验设计

> 目的：通过消融实验与对比实验，量化验证本系统 LLM-as-Judge 评估方法（锚点示例三档校准 + 计分公式注入）相对基线版本的优劣，并回答两个核心问题：
>
> 1. **稳定性**：同配置重复评估的方差是否显著低于旧版？
> 2. **准确性**：对已知对错样本（金标探针）的判定是否正确？
>
> 实验不涉及生产代码改动，全部通过前端「评估配置」界面或既有评估记录完成。

***

## 一、实验对象

### 1.1 被评估材料（固定不变）

固定使用同一份抽取结果作为"被测物"，控制变量：

| 项      | 值                                       |
| ------ | --------------------------------------- |
| 语料     | 三国人物关系（819 字，含时间信号、否定传闻、事件实体、指代消解等多种现象） |
| 抽取任务   | 任务 2095509498512379905（LLM 抽取）          |
| 抽取结果规模 | 102 实体（其中事件实体 53 个）、66 关系               |

另取两份历史抽取结果作为扩展验证材料：

| 抽取任务                | 语料           | 历史评估次数 | 用途       |
| ------------------- | ------------ | ------ | -------- |
| 2094406639339233282 | 诉讼语料（1225 字） | 6 次    | 旧版方差基线   |
| 2095492178784129026 | 三国语料（早期抽取）   | 4 次    | 裁判模型横向对比 |

### 1.2 变量定义

| 变量        | 取值                                                  | 说明                                               |
| --------- | --------------------------------------------------- | ------------------------------------------------ |
| **裁判提示词** | 旧版 / 新版                                             | 新版 = 三档锚点示例 + 计分公式 + 事件实体规范；旧版 = 抽象 criteria 无示例 |
| **裁判模型**  | deepseek-chat / deepseek-v4-pro / deepseek-v4-flash | 均已在 llm\_model 表注册                               |
| **抽样数量**  | 全量（sampleSize=0）                                    | 排除抽样噪声，聚焦裁判方差                                    |
| **重复次数**  | 每配置 ≥3 次                                            | 计算极差与标准差                                         |

## 二、实验设计

### E1 消融实验：提示词版本（核心实验）

**问题**：评估稳定性的提升来自新版提示词的哪个组件？

**设计**：同一抽取结果、同一裁判模型（deepseek-chat）、全量抽样，对比以下配置（E1-A 与 E1-B 已有历史数据，无需重跑）：

| 配置   | 提示词                        | 数据来源                       |
| ---- | -------------------------- | -------------------------- |
| E1-A | 旧版（抽象规则，无示例无公式）            | 历史记录（已有 10 次）              |
| E1-B | 新版（锚点三档 + 计分公式 + 事件规范）     | 历史记录（已有 3 次）               |
| E1-C | 新版去锚点（保留事件规范与公式，删除全部锚点示例行） | 需临时修改 criteria 后跑 3 次，跑完还原 |
| E1-D | 新版去公式（保留锚点，删除计分公式段）        | 同上                         |

> E1-C / E1-D 通过临时编辑 `pybackend/api/evaluation.py` 中对应 criteria 文本并重启服务完成，实验后必须还原（git checkout）。每组只改一处，其余变量严格不变。

**观测指标**：

1. overall 极差（max−min）与标准差（主指标）
2. 逐指标极差（重点看旧版波动大的谓词合理性、实体边界）
3. 判 1 档占比分布（新版预期将摇摆样本收敛到 1，而非在 0/2 间横跳）

**已有基线数据（E1-A / E1-B）**：

| 配置                                       | 重复次数 | overall 序列                                          | 极差         |
| ---------------------------------------- | ---- | --------------------------------------------------- | ---------- |
| 旧版（任务 2094406639339233282）               | 6    | 0.7200 / 0.8711 / 0.7500 / 0.8622 / 0.8956 / 0.7911 | **0.1756** |
| 旧版（任务 2095492178784129026，裁判混用三模型）       | 4    | 0.8594 / 0.7346 / 0.8614 / 0.7177                   | 0.1437     |
| 新版（任务 2095509498512379905，deepseek-chat） | 3    | 0.8636 / 0.8652 / 0.8652                            | **0.0016** |

新版三次逐指标明细（均值 / 极差）：

| 指标      | 均值     | 极差     |
| ------- | ------ | ------ |
| 三元组忠实度  | 0.7677 | 0.0151 |
| 谓词合理性   | 0.7854 | 0.0228 |
| 双时态正确性  | 1.0000 | 0.0000 |
| 证据句有效性  | 0.7702 | 0.0075 |
| 实体边界正确性 | 1.0000 | 0.0000 |

### E2 对比实验：裁判模型

**问题**：三个候选裁判模型在本评估框架下的尺度差异与适用性？

**设计**：同一抽取结果（2095509498512379905）+ 新版提示词 + 全量抽样，每个裁判模型各跑 3 次（其中 deepseek-chat 的 3 次复用 E1-B 数据，实际新增 v4-pro 与 v4-flash 各 3 次）。

**已有参考数据**（旧版提示词、任务 2095492178784129026、各 1 次）：

| 裁判模型              | overall | 特征                                 |
| ----------------- | ------- | ---------------------------------- |
| deepseek-chat     | 0.7346  | 严格执行规则；旧版下砍事件实体（无规范可依）             |
| deepseek-v4-pro   | 0.8614  | 语义理解最深；但同结果两次评估极差曾达 0.10（推理模型非确定性） |
| deepseek-v4-flash | 0.7177  | 跨指标重复扣分（结构问题同时罚忠实度与谓词）             |

**观测指标**：各模型 overall 均值（模型间尺度差）、各模型内部 3 次极差（模型自身稳定性）、金标探针命中率（见 E4）。

**预期结论形态**：给出"日常迭代裁判 / 重要验收裁判 / 不推荐裁判"的模型推荐表。

### E3 稳定性实验：重复评估一致性

**问题**：新方法的方差水平是否可复现（不依赖特定任务的巧合）？

**设计**：E1/E2 的所有配置天然产出重复数据，汇总为一张"配置 × 极差"矩阵，不单独跑新实验。若需要加强证据，可在任务 2094406639339233282（诉讼语料）上用新版提示词 + deepseek-chat 补跑 3 次，与同任务旧版 6 次（极差 0.1756）直接对照——**这是同一任务上的最干净消融**。

### E4 准确性实验：金标探针

**问题**：稳定不等于正确（一致地判错也稳定）。需要验证判定准确性。

**设计**：从被测抽取结果中人工核对一组"已知标准答案"的样本（金标探针），检查评估报告 details 中的 verdict 是否符合预期：

| 探针类型 | 样本                              | 金标预期 verdict | 依据              |
| ---- | ------------------------------- | ------------ | --------------- |
| 否定关系 | 周瑜-\[并无]->诸葛亮                   | 2（判 0 才是错杀）  | 原文"与诸葛亮并无直接冲突"  |
| 否定关系 | 诸葛亮-\[并未]->诸葛亮借东风助周瑜火攻          | 2            | 原文"正史中并无此事"     |
| 否定关系 | 周瑜-\[并未]->周瑜被气死                 | 2            | 原文"实则周瑜于210年病逝" |
| 事件实体 | 「张角率领黄巾军发动起义」type=事件            | 2            | 完整动宾短语属规范命名     |
| 时间关系 | 起义-\[随后发生]->曹操自任司空（vt 184\~196） | 2            | 时间区间与原文一致       |

**判读**：每次评估报告中逐条核对探针样本的 verdict 与 reason；命中率 = 正确探针数 / 探针总数。E1/E2 每次运行的报告均可回溯探针命中情况（评估记录 result 字段含 details）。

### E5 对比实验：抽取质量监控场景验证（可选）

**问题**：评估方法能否区分"抽取质量真实差异"？（灵敏度）

**设计**：利用已有的三份不同质量抽取结果（旧 prompt 诉讼 45 条、新 prompt 三国 41 条早期版、当前 66 条版），全部用"新版提示词 + deepseek-chat + 全量"评估一次，检查分数排序是否符合人工判断的质量排序。若分数单调反映质量梯度，说明方法具备区分度，不只是"稳定地输出同一个数"。

## 三、数据收集规范

1. **登记表**：每跑一次评估，在实验记录表中登记一行：评估记录 id、日期、裁判模型、提示词版本、sampleSize、overall、逐指标分、token 消耗、探针命中数。评估记录 id 是唯一键，可随时回查 MySQL `evaluation_record` 表。
2. **历史数据回收**：旧版 10 次 + 新版 3 次已从 `evaluation_record` 表回收完毕（见 §2 各表），无需重跑。
3. **控制项**：所有实验 sampleSize=0（全量）；每次评估间隔无要求（方差与时间无关）；E1-C/E1-D 临时改动的 criteria 文本以 git diff 形式存档到实验记录中。
4. **样本量说明**：每配置 3 次重复对小极差的统计功效有限（n=3 的标准差估计本身有噪声），若两组极差差一个数量级以上（如 0.0016 vs 0.17）即可下结论；若接近则补至 5 次。

## 四、预期结果与判读标准

| 实验 | 判定"方法有效"的标准                                                                              |
| -- | ---------------------------------------------------------------------------------------- |
| E1 | 新版 overall 极差 < 0.03（旧版实测 0.1756）；E1-C/E1-D 定位出锚点示例是主要贡献项（预期 E1-C 极差回升至 0.05+，E1-D 小幅回升） |
| E2 | 三模型 overall 差异 < 0.10（旧版提示词下实测三模型差 0.14）；v4-pro 内部极差若仍 >0.05 则确认"推理模型不宜做裁判"              |
| E3 | 新版在 ≥2 个不同任务上极差均 < 0.03                                                                  |
| E4 | 探针命中率 ≥ 90%（允许个别判 1，不允许判 0）                                                              |
| E5 | 三份质量不同的抽取结果分数排序与人工质量判断一致                                                                 |

**整体结论模板**（实验完成后填写）：

- 稳定性：新旧极差对比 \_\_\_ vs \_\_\_，方差降低 \_\_\_%

- 准确性：探针命中 ___/___

- 模型推荐：日常裁判用 \_\_\_，验收裁判用 \_\_\_，不推荐 \_\_\_

- 组件贡献：锚点示例贡献 \_\_\_，计分公式贡献 \_\_\_，事件规范贡献 \_\_\_

## 五、有效性威胁与控制

| 威胁                            | 控制措施                                        |
| ----------------------------- | ------------------------------------------- |
| 旧版历史数据非同日采集，可能混入其他变量          | E3 用同一任务新旧对照；且旧版 10 次数据本身分布一致（极差均 >0.14）    |
| E1-C/E1-D 临时改动代码引入风险          | 只删文本段落不改逻辑；跑完立即 git checkout 还原；改动以 diff 存档 |
| 裁判模型 API 侧行为随时间漂移             | 所有新增实验集中在同一天完成；记录每组的日期                      |
| 探针样本过少（5 条）导致 E4 结论脆弱         | 探针仅作准确性下限验证，不单独支撑结论；与 E5 灵敏度实验互相印证          |
| 三个裁判模型与抽取模型（v4-flash）存在同源自评偏差 | 主裁判 deepseek-chat 与抽取模型不同源；E2 结果表注明此局限      |
| 样本量小（n=3）统计功效不足               | 判读标准采用数量级差异原则；接近时补跑至 n=5                    |

***

## 六、实验执行顺序建议

1. **E2 补跑**（v4-pro ×3、v4-flash ×3）：不动代码，纯前端操作，先积累数据
2. **E3 补跑**（诉讼任务 + 新版提示词 + deepseek-chat ×3）：同任务新旧对照
3. **E1-C / E1-D**：临时改 criteria 各跑 3 次后还原
4. **E4**：对已产出的所有报告回溯探针 verdict（零成本）
5. **E5**（可选）：三份抽取结果各评 1 次
6. 汇总登记表 → 填写结论模板 → 结论回填本文档附录
