诉讼证据图谱 MVP

基于 KGraph 知识图谱的诉讼证据时间线与因果链梳理工具 — 产品需求文档（PRD v1.0）

产品：诉讼证据图谱（EvidenceGraph）
版本：MVP v1.0
面向用户：诉讼律师
文档状态：待评审

1. 背景与目标

1.1 问题

诉讼律师在案件办理中需要梳理大量证据材料（合同、邮件、转账记录、聊天截图、证人证言等），核心痛点：

  • 时间线还原耗时：人工从数十份证据中提取时间、主体、行为，整理时间线需 3-5 天
  • 事实遗漏风险：人工梳理易遗漏关键事实节点，直接影响诉讼请求的事实支撑
  • 证据矛盾难发现：多份证据对同一事实的表述冲突（如金额、日期不一致），人工比对极易遗漏
  • 因果关系不清晰："违约行为→损失结果→因果关系"的链条需律师在脑中建构，难以可视化呈现给法官/客户

1.2 产品决策

利用 KGraph 的双时态知识图谱能力，将非结构化证据自动转化为结构化时间线 + 因果链图 + 矛盾点清单，每条事实断言可回溯到证据原文。

1.3 目标（可观测）

  • 律师上传证据后，系统在 10 分钟内生成可审查的时间线与因果链初稿
  • 律师可通过点击时间线节点直接跳转到对应证据原文片段
  • 系统自动标注证据矛盾点（时间/金额/主体冲突），供律师复核

2. 范围

2.1 P0 核心旅程

创建案件→ 上传证据→ 自动抽取→ 时间线/因果链/矛盾点→ 人工确认修正→ 导出报告

完成证据：律师在时间线图上看到按时间排序的事实节点，点击节点可查看证据原文；因果链图展示行为间因果关系；矛盾点清单列出冲突项。

2.2 P1 支持功能

  • 多案件对比（同一当事人不同案件的事实串联）
  • 法条推荐（基于事实要素匹配相关法条）
  • 文书草稿辅助（基于时间线+因果链生成事实陈述段落）

2.3 明确排除

  • 自动生成完整法律文书（仅辅助事实陈述段落）
  • 裁判结果预测
  • 证据合法性/真实性判断（仅做事实抽取与矛盾检测，不做法律评价）
  • 多用户协作/审批流

3. 产品契约

要素定义
主要用户诉讼律师（主办/协办），需处理证据梳理的执业律师
核心任务将散乱证据转化为结构化时间线 + 因果链，辅助事实认定

5. 功能需求

FR-01 案件创建 P0

目的：律师创建新案件，作为证据和图谱的容器。

触发：律师在案件列表页点击"新建案件"。

处理规则：

  • 必填字段：案件名称、案件类型
  • 案件名称不可为空，长度 1-100 字符
  • 创建后案件状态为 draft

结果：生成案件记录，跳转到案件详情页（证据上传区）。

FR-02 证据上传与解析 P0

目的：律师上传证据材料，系统解析为文本。

触发：在案件详情页上传文件。

处理规则：

  • 支持格式：PDF、DOCX、TXT、图片（PNG/JPG，需 OCR）
  • 单文件大小上限：[TBD，建议 50MB]
  • 单案件证据数量上限：[TBD，建议 100 份]
  • 上传后自动解析文本，记录页数
  • 解析失败的文件标记为 parse_failed，律师可重新上传

结果：证据列表展示文件名、页数、解析状态。

异常：不支持的格式 → 提示"暂不支持该格式"；解析失败 → 标记并允许重试。

FR-03 知识抽取（LLM 三阶段） P0

目的：调用 KGraph LLM 抽取能力，从证据文本中抽取实体、关系、时间锚点、因果边。

触发：律师点击"开始抽取"按钮（需至少上传 1 份已解析的证据）。

处理规则：

  • 调用 KGraph /api/extract 端点，传入所有证据文本拼接
  • 抽取实体类型限定为法律场景：person / organization / action / amount / time / subject_matter
  • 抽取关系谓词限定为法律行为：签订 / 支付 / 交付 / 违约 / 通知 / 解除 / 起诉 / 判决 等
  • 案件状态切换为 extracting，展示进度
  • 抽取完成后状态切换为 ready

结果：生成实体、关系、时间锚点、因果边数据，写入 Neo4j 图谱。

异常：抽取超时（[TBD，建议 30 分钟]）→ 标记失败，允许重试；部分证据抽取失败 → 记录并继续，不中断整体。

FR-04 时间线可视化 P0

目的：将时间锚点 + 关联关系按时间顺序展示为交互式时间线。

触发：抽取完成后，律师进入"时间线"标签页。

处理规则：

  • 按 normISO 升序排列所有时间锚点
  • 每个时间节点展示：时间、主体、行为（关系谓词）、客体
  • 节点颜色按主体区分（同一主体同色）
  • 点击节点 → 右侧面板展示该节点的 evidenceText 原文片段 + 证据文件名 + 页码
  • precision 为 year/month 的节点显示为区间（如"2023 年"或"2023 年 3 月"）

结果：律师可沿时间轴浏览案件事实全貌。

异常：无时间锚点 → 提示"未抽取到时间信息"。

FR-05 因果链可视化 P0

目的：将因果边展示为有向图，呈现法律因果关系链。

触发：律师进入"因果链"标签页。

处理规则：

  • 节点 = 行为实体，边 = 因果关系（cause → effect）
  • 边上标注 signalWord（如"导致"）
  • 点击节点 → 展示该行为的 evidenceText
  • 支持高亮某条因果路径（如"违约 → 损失 → 赔偿请求"）

结果：律师可直观查看因果关系链，用于构建诉讼请求的事实基础。

异常：无因果边 → 提示"未抽取到因果关系"。

FR-06 矛盾点检测 P0

目的：自动检测多份证据间的事实冲突，降低遗漏风险。

触发：抽取完成后自动运行，律师进入"矛盾点"标签页查看。

处理规则：

  • time_conflict：同一行为在不同证据中时间不一致（如付款日期）
  • amount_conflict：同一笔金额在不同证据中数值不一致
  • party_conflict：同一主体在不同证据中名称/角色不一致（需结合 aliasMap）
  • fact_conflict：同一事实的表述相反（如"已交付"vs"未交付"）
  • severity 判定：金额/时间差异 > 阈值 → high；表述相反 → high；名称差异 → medium
  • 每条矛盾点列出涉及的证据片段引用，律师可逐条跳转核验

结果：矛盾点清单按 severity 降序排列，律师可标记"已处理"。

设计说明：矛盾检测基于图谱中的实体/关系对齐，而非简单文本匹配。例如，两笔"付款"行为若主体和客体相同但时间不同，则判定为 time_conflict。

FR-07 证据原文回溯 P0

目的：任何抽取结果（实体/关系/时间/因果/矛盾点）均可追溯到证据原文。

触发：律师在时间线/因果链/矛盾点中点击任意节点或条目。

处理规则：

  • 右侧面板展示 evidenceText（原文片段）
  • 展示证据文件名、页码
  • 高亮原文中对应的文本片段（基于 evidenceSpans）
  • 支持"在原文中查看"按钮，跳转到证据全文浏览并定位到该片段

结果：律师可核验每条断言的真实性，建立对 AI 抽取结果的信任。

FR-08 人工确认与修正 P0

目的：律师对抽取结果进行确认或修正，形成可信的案件事实图谱。

触发：律师在时间线/因果链中对节点进行操作。

处理规则：

  • 每个实体/关系/时间锚点有 verified 状态（默认 false）
  • 律师可"确认"（verified=true）、"编辑"（修改名称/时间/金额）、"删除"（错误抽取）
  • 编辑后需保留 evidenceText（不可删除证据）
  • 修正操作记录审计日志（操作人、时间、修改前后值）

结果：案件状态切换为 reviewed，图谱数据为律师确认版本。

FR-09 导出报告 P0

目的：将确认后的时间线、因果链、矛盾点导出为文档，用于案件讨论或提交。

触发：律师点击"导出报告"。

处理规则：

  • 导出格式：[TBD，建议 DOCX + PDF]
  • 报告内容：案件基本信息、时间线表、因果链图（截图）、矛盾点清单、证据引用索引
  • 仅导出 verified=true 的条目

结果：生成可下载的报告文件。

6. 共享规则与异常

6.1 抽取质量阈值

指标阈值处理
实体置信度< 0.5标记为"低置信"，默认不 verified，律师需复核
关系置信度< 0.5同上
证据覆盖率< 30%提示"证据文本可能未完整解析"，建议检查

6.2 指代消解规则

  • 同一当事人在不同证据中的别名（甲方/XX公司/被告）通过 aliasMap 合并为同一实体
  • 合并后以出现频率最高的全称为 canonicalName
  • 律师可手动合并/拆分实体

6.3 数据隔离

  • 每个案件的图谱数据独立存储（Neo4j 中按 caseId 分区）
  • 律师只能查看自己创建的案件（MVP 阶段单用户）

6.4 异常处理汇总

场景处理
证据解析失败标记 parse_failed，允许重新上传
抽取超时标记失败，允许重试（最多 [TBD] 次）
抽取结果为空提示"未抽取到有效信息"，建议检查证据文本质量
无时间锚点时间线页提示，不阻断因果链/矛盾点展示
无因果边因果链页提示
矛盾点误报律师可标记"误报"，不影响图谱数据
